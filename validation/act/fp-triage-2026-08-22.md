# Pour FP triage — 2026-08-22 capture (440-testcase sample, asserted band)

Manual read of every pour false-positive fixture from `results/merged-2026-08-22.jsonl`.
Verdicts: **real** (pour asserts a failure ACT deems passed/inapplicable — upstream candidate) or
**artifact** (correct finding counted against the wrong ACT rule by the criterion-level scoring
policy — not a pour defect).

## Real — upstream filing candidates

1. **Contrast asserted on ACT-exempt text** (3 FPs, `afw4f7`/`09o5cg`). Symbol-only text
   (`09o5cg` Passed Ex 6: a paragraph of `----====++++…` at 3.66:1) and letter-as-icon glyphs
   (`afw4f7` Passed Ex 7 / `09o5cg` Passed Ex 6: `<button aria-label="Close">X</button>`) are
   expected *passed* by the ACT contrast rules; pour's `color-contrast` /
   `color-contrast-enhanced` assert failures. Axe returns no finding on all three (TN). Given
   pour's "report what it cannot prove" ethos, asserting on ACT-consensus-exempt text is worth an
   upstream issue.
2. **`button-name` on `<button role="none" disabled>`** (1 FP, `97a4e1` Inapplicable Ex 5). With
   the element disabled (not focusable), `role="none"` holds and the element is out of scope for
   the button-name rule; pour flags it.
3. **`link-name` misses descendant `aria-labelledby`** (1 FP, `c487ae` Passed Ex 8):
   `<a href><img aria-labelledby="id1"></a>` — the link's name-from-content includes the image's
   aria-labelledby name, so the link is correctly named; pour flags it empty. Accessible-name
   computation gap.
4. **Language rules skip ACT applicability conditions** (4 FPs, `de46e4`/`off6ek`/`ucwvc8`).
   `valid-lang-parts` flags invalid `lang` values on elements whose text is overridden by a
   descendant `lang` or entirely `display:none` (ACT: passed/inapplicable — the SC concerns text
   that *uses* the language); `html-lang` flags a completely empty `<html></html>` page (ACT:
   inapplicable without text). Defensible strictness, but a divergence from ACT consensus worth
   raising upstream.

## Artifact — scoring policy, not pour

- **`c487ae` Inapplicable Ex 4** (`<a aria-hidden="true" href>…</a>`): pour's `aria-hidden-focus`
  finding is a *correct* 4.1.2 issue (focusable content hidden from AT); it counts as an FP only
  because the fixture tests a different ACT rule on the same criterion. This is the documented
  generosity of criterion-level matching; an exact engine-rule → ACT-rule map would reclassify it.

## Tally

Of 15 criterion-level FPs in the sample, ~9 fixtures inspected covering all hotspots: 9 real
across 4 defect classes, 1 artifact. The 4 classes are small, well-defined applicability/name-
computation gaps — exactly the kind of finding the candidacy pipeline is meant to hand upstream
(engine-candidacy-pipeline.md, Stage 5 / benchmarks §6 stewardship).

## Recheck 2026-09-01 (pour 1.37.0, surea11y 1.7.0)

Re-ran every fixture of the eight ACT rules above with the current bundles
(`--engines pour,surea11y --rules afw4f7,09o5cg,97a4e1,c487ae,de46e4,off6ek,ucwvc8,4b1c6c`).

- Pour classes 1–3 persist unchanged in 1.37.0 (contrast on `afw4f7`/`09o5cg` Passed Example 7,
  `button-name` on `97a4e1` Inapplicable Example 5, `link-name` on `c487ae` Passed Example 8).
  Contrast also asserts on `09o5cg` Inapplicable Examples 6 and 7 — label text of a disabled
  control, which ACT's "disabled label" applicability exemption excludes — a third sub-case of
  class 1. Class 4 narrows to `valid-lang-parts` (`de46e4` Passed Example 4, Inapplicable 3–5,
  `off6ek` Inapplicable 5): the `html-lang` hits on empty documents (`ucwvc8` Inapplicable 2–3,
  `97a4e1` Passed 6, `c487ae` Passed 9) are correct under ACT `b5c3f8`, whose applicability has
  no content condition, and count as FPs only through criterion-level scoring. Same for
  surea11y's `html-lang-attr-present` on those fixtures.
- **surea11y `4b1c6c` (11 FP)** is `iframe-title-unique`, not the 1.7.0 rule
  `identical-iframes-same-purpose` (which already reports differing resources as `cantTell`):
  it fails any two frames sharing a title attribute, including Passed Examples 1, 4–9 where the
  frames embed the same or equivalent resource, and Inapplicable Example 5.
- Upstream filings prepared from this recheck: pour — presentational-role conflict ignoring
  `disabled`, name-from-content ignoring descendant `aria-labelledby`, contrast on
  non-human-language text / icon glyphs / disabled labels, `valid-lang-parts` applicability;
  surea11y — `iframe-title-unique` vs ACT 4b1c6c.
